# План разработки CRM агентства недвижимости (Ереван)

Документ описывает, как будет реализована CRM по бизнес-требованиям (БТ), и фиксирует решения по спорным местам.

## 1. Принятые решения по открытым вопросам

| #    | Вопрос                                                                               | Решение                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---- | ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

## 2. Архитектура

NocoDB — единственное хранилище бизнес-данных (НФТ-1). Все остальные компоненты работают с ним только через собственный бэкенд, который обращается к NocoDB по API. У пользователей CRM нет ни доступа к NocoDB, ни его токена.

```
[Браузер: React SPA, mobile-first]
        │ HTTPS, httpOnly cookie
        ▼
[API (BFF), NestJS] ── права, валидация переходов, аудит, дедупликация
   │       │                          │
   │       ▼                          ▼
   │   [Redis] сессии, блокировки, очереди BullMQ, кэш дашбордов
   ▼
[NocoDB REST API] ──► [PostgreSQL]      [MinIO/S3] фото
   ▲        ▲
   │        └── [Worker] биллинг, dunning, просрочка, саги, outbox уведомлений
   └── [Parser] list.am, отдельный контейнер (НФТ-7)
                 [Telegram Bot] привязка аккаунтов, отправка из outbox (НФТ-8)
```

### Стек

- **Монорепозиторий** на pnpm: `apps/web`, `apps/api`, `apps/worker`, `apps/parser`, `apps/bot`, `packages/shared` (типы, zod-схемы, коды этапов, матрица прав), `packages/nocodb-client`.
- **Бэкенд:** Node 22, TypeScript, NestJS, argon2, zod.
- **Фронтенд:** React, Vite, TanStack Query и Table, dnd-kit, Mantine, i18n (сначала ru).
- **Парсер:** undici и cheerio. Если list.am отдаёт контент только через JS — Playwright. Обрезка фото — sharp.
- **Бот:** grammY.
- **Инфраструктура:** Docker Compose на VPS, Caddy (TLS), GitHub Actions, Sentry, uptime-мониторинг, ежедневный бэкап Postgres и MinIO.

### Как обходим ограничения NocoDB

1. **Схема данных хранится в коде.** Таблицы и поля создаются версионированными миграциями через meta API NocoDB.
2. **В NocoDB нет транзакций.** Закрытие сделки выполняется сагой: сначала пишется запись события с ключом идемпотентности, затем воркер выполняет шаги. Каждый шаг можно безопасно повторить, отдельная сверка находит «зависшие» события.
3. **Уникальность и захват карточек.** Перед проверкой уникальности телефона клиента, дедупликацией по URL и захватом карточки партнёром берётся блокировка в Redis.
4. **Параллельные правки.** Оптимистичная блокировка: поле `version` проверяется и увеличивается под блокировкой Redis (условного UPDATE в NocoDB нет). При конфликте пользователь получает сообщение «карточку изменил другой пользователь».
5. **Аудит только на дописывание (НФТ-3).** API не предоставляет операций изменения и удаления аудита.
6. **Аналитика.** История переходов хранится в `stage_transitions`. Агрегаты считает бэкенд и кэширует в Redis.

## 3. Модель данных (таблицы NocoDB)

- `users`: логин, хеш пароля, роль, права (выдача доступов, удаление карточек, справочники), статус, `must_change_pwd`, `created_by`, `telegram_chat_id`
- `pipeline_stages`: воронка, код, название, порядок, `is_system`
- `listings`: этап, название, описание, цена, район, тип, комнаты, контакты, телефон, URL (уникальный), источник, ответственный, партнёр-источник, дата встречи, исход, комиссия %, `last_activity_at`
- `listing_photos`
- `clients`: имя, телефон (уникальный), мессенджер, бюджет, предпочтения, сроки, источник, ответственный, партнёр-источник, согласованная и финальная цена, фактическая комиссия, причина отказа, `last_activity_at`
- `client_listing_links` (связь клиент ↔ объявление): статус, дата показа
- `showings`, `comments` (ручные и системные), `stage_transitions`, `audit_events`
- `deals`, `partner_rewards`
- `subscriptions`, `payments`, `payment_methods` (только токен провайдера)
- Справочники: одна таблица `dictionary_items` с полем `kind` (source, district, property_type, reject_reason)
- `settings` (в т.ч. настройки парсера), `parser_runs`, `domain_events` (саги), `notifications_outbox`, `user_prefs`

## 5. Риски

1. **list.am:** защита от ботов, скрытый телефон, смена вёрстки, условия использования сайта. Проверяется на этапе 0.
2. **Производительность API NocoDB** при росте данных. Меры: кэш, денормализованные поля, индексы в Postgres.
3. **Платёжный провайдер** — юридический вопрос, решить до этапа 8.
4. **Отсутствие транзакций** — саги и сверка.
